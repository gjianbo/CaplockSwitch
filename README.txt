CapsSwitch 1.0 — 使用说明
===============================================================================

一、这是什么
-------------------------------------------------------------------------------
把键盘上位置很好、但使用频率极低的 Caps Lock 键，重映射成「切换输入法」。

  * 单独按 Caps Lock  -> 发送你配置的输入法切换快捷键（默认 Ctrl + Space）
  * Shift + Caps Lock -> 放行给系统，执行原生大写锁定（两种 Shift 都行）
  * 暂停状态下        -> 完全不干预，Caps Lock 恢复系统原生行为

程序没有主窗口，常驻托盘，只靠一个托盘图标交互。适合从 Mac 转过来、
习惯了「按 Caps 切中英文」的用户。


二、安装与运行
-------------------------------------------------------------------------------
1) 选中与你的系统位数一致的 exe：
     * 64 位系统（Win10/11、Server 2022/2025）  -> CapsSwitch-x64.exe
     * 32 位系统（部分 Win7）                   -> CapsSwitch-x86.exe
2) 直接双击运行。首次运行会常驻托盘，不会弹出任何窗口。
3) 不需要管理员权限。不需要安装，删除文件即卸载干净
   （如需同时清理配置，删掉 %APPDATA%\CapsSwitch 目录即可）。

本程序不写系统目录、不装服务、不改注册表里除「开机启动」项以外的任何内容。


三、操作方式
-------------------------------------------------------------------------------
托盘图标左键单击    切换「启用 / 暂停」

托盘图标右键菜单
    启用（Caps→输入法）      单选，与「暂停」互斥
    暂停（原生 Caps）        单选
    ----------------------
    开机启动                 勾选项
    设置...                  打开设置窗口
    ----------------------
    退出                     卸载键盘钩子、移除托盘图标、退出进程

全局热键            Ctrl + Alt + C    等价于托盘左键单击

图标状态
    启用    绿色图标，tooltip 显示「已启用（Caps→输入法，Shift+Caps→大写）」
    暂停    灰色图标，tooltip 显示「已暂停（原生 Caps Lock）」


四、配置文件
-------------------------------------------------------------------------------
路径：%APPDATA%\CapsSwitch\config.ini
（例如 C:\Users\你的用户名\AppData\Roaming\CapsSwitch\config.ini）

[General]
Enabled=1        ; 0/1  是否启用 Caps 替换
AutoStart=0      ; 0/1  是否开机启动（仅作记录，实际以注册表为准）
HotkeyMode=0     ; 0-3  切换输入法的快捷键模式

HotkeyMode 取值：
    0 = Ctrl + Space          Windows 默认输入法切换（默认值）
    1 = Win + Space           Win10/11 输入法循环
    2 = Shift + Space         部分第三方输入法
    3 = Ctrl + Shift + Space  传统中文输入法

写入时机（严格按规格）：
    启动时只读取、不写盘；只有在托盘菜单切换、或设置窗口里改动过，
    才会把配置落盘。所以全新安装时该文件可能还不存在，属正常。
    仓库根目录的 CapsSwitch.ini 是一份带注释的示例，可直接复制改名使用。


五、开机启动
-------------------------------------------------------------------------------
实现方式：在 HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
写入名为 CapsSwitch 的字符串值，内容为当前 exe 的完整路径（带引号）。

  * 只写 HKCU，因此不需要管理员权限，也不会弹 UAC；
  * 勾选时写入，取消勾选时删除该值；
  * 启动时读注册表判断当前状态（托盘菜单的勾选状态以此为准）；
  * 如果 exe 被移动到别的目录，下次启动会自动把注册表里的旧路径更新为新路径。


六、构建
-------------------------------------------------------------------------------
依赖：Visual Studio 2019/2022/2026，安装时勾选「使用 C++ 的桌面开发」
     （含 MSVC 工具集与 Windows SDK）。

Windows 命令行：
    build.bat              构建 x64 + x86（默认）
    build.bat nocrt        构建无 CRT 精简版

Git Bash / MSYS2（不依赖注册表定位 SDK，实测验证过的路径）：
    bash tools/build_local.sh
    bash tools/build_local.sh nocrt

产物在 bin\ 目录。

重新生成托盘图标（可选，需要 Python 3，无第三方依赖）：
    python tools/make_icons.py
    脚本会读取 icons\source_on.png（绿）与 icons\source_off.png（灰）
    两张设计稿，裁掉透明留白后按面积平均降采样，再打包成含
    16x16 / 32x32 两档的 ICO。换图标时直接替换这两张 PNG 重跑即可。


七、兼容性与已知限制
-------------------------------------------------------------------------------
支持的平台
    Windows 7 Sp1 及以上、Windows 10/11、Server 2012 及以上、
    Server 2022 / 2025。x64 与 x86 两个版本各自独立。

关于 Windows 7 的注意事项
    本工程用 MSVC 14.51（VS 2026 工具集）编译。微软自 VS2022 17.10 起
    已把 Windows 7 移出官方支持矩阵，代码本身只用了 Win7 就有的 API，
    但在 Win7 上属于「未官方支持」状态。如果 Win7 是硬性目标平台，
    建议改用 v142/v141 工具集重新编译一遍并实机验收。

已知限制
    * UAC 提权窗口、以及部分以管理员权限运行的全屏程序，在非管理员
      运行时收不到键盘事件。这是 Windows 的 UIPI 机制限制，不是 bug。
      需要在提权窗口里也生效的话，把 src\CapsSwitch.manifest 中的
      requestedExecutionLevel 改成 requireAdministrator 后重新编译。
      代价是每次启动都会弹 UAC，且不能再用 HKCU Run 项静默自启。
    * 如果 Caps Lock 的输入法切换快捷键已被其他软件占用（例如某些
      输入法自带 Ctrl+Space 拦截），本程序不做规避，请自行在设置里
      换一种模式。
    * 系统休眠 / 唤醒后钩子会自动保持，无需重新注册。
    * 托盘图标在 16x16 这一档，「Caps」五个字母会被压缩成一条模糊的
      横向亮带 —— 这是像素数决定的，任何 5 字母字标在 16px 下都一样。
      状态区分主要靠颜色（绿 / 灰），tooltip 里也有完整文字说明。
      如果希望 16px 下也清晰，可以另做一版简化的小尺寸设计稿
      （例如只保留字母 C，或只留键帽 + 状态点），单独替换即可。


八、源码结构
-------------------------------------------------------------------------------
src\app.h            全局常量、共享状态、各模块对外接口
src\main.cpp         进程入口、消息循环、状态中枢
src\hook.cpp         WH_KEYBOARD_LL 键盘钩子与按键注入（核心逻辑集中在此）
src\tray.cpp         托盘图标、tooltip、右键菜单
src\settings.cpp     设置窗口（CreateWindowEx 手工搭控件，无资源模板）
src\config.cpp       config.ini 读写、开机启动注册表项
src\crt_free.cpp     无 CRT 构建专用的进程入口与内存函数（默认构建不含）
src\resource.h       资源与命令 ID
src\CapsSwitch.rc    资源脚本
src\CapsSwitch.manifest  应用清单（DPI、主题、目标系统、执行权限）
icons\source_on.png  启用态图标设计稿（绿）
icons\source_off.png 暂停态图标设计稿（灰）
icons\IDI_ON.ico     由设计稿生成的托盘图标（16x16 + 32x32）
icons\IDI_OFF.ico    同上
tools\make_icons.py  图标生成脚本（纯标准库）
tools\build_local.sh 不依赖注册表的构建脚本（Git Bash / MSYS2）


九、实现说明（相对规格书的几处落地取舍）
-------------------------------------------------------------------------------
1) 设置窗口的「确定 / 取消」语义

   规格里同时写了「复选框实时生效」「下拉框选择后即时保存」和
   「取消放弃未保存修改」，字面上互相冲突。落地取舍是：

       任一控件变化 -> 立即生效并落盘      （满足前两条）
       打开窗口时对配置拍一张快照
       「取消」 -> 把快照写回去            （满足第三条，放弃本次改动）
       「确定」 -> 直接关闭，不做额外回滚

   如果期望的是标准对话框语义（改动只在点「确定」后才生效），
   把 settings.cpp 的 OnCommand 改成「只改局部变量、确定时统一提交」即可。

2) 位数选择

   规格只写了「Windows 7 / 10 / 11 / Server 2022 / 2025」，没有指定位数。
   考虑到大量 Win7 装机是 32 位，这里同时产出 x64 与 x86 两个版本。

3) 体积

   规格写的「< 100KB」经确认不是硬性要求。默认构建用静态 CRT（/MT），
   零运行时依赖，x64 约 121KB、x86 约 105KB，可读性与可维护性优先。
   如果哪天真的需要极致体积，build.bat nocrt 会走一条完全不带 C 运行库
   的构建路径（自备进程入口），x64 约 27KB，代价是失去 /GS 栈保护。

4) 开机启动的事实来源

   config.ini 里保留 AutoStart 字段（规格要求），但程序判断「当前是否
   开机启动」一律以注册表 Run 项为准，避免两边不一致。写失败时不会
   只改内存状态，菜单勾选与实际行为永远同步。

5) 规格未提但补上的两点

   * Explorer 崩溃重启后会广播 TaskbarCreated，不重新挂载的话托盘图标
     会永久消失。tray.cpp 已处理。
   * 按住 Caps 不放时系统会产生自动重复的 KEYDOWN，这里只在首次按下
     发送快捷键，避免连发一串切换。
