## 这个版本修什么

修复一个会影响**剪贴板粘贴**的问题：开着 CapsSwitch 时，用 PixPin 之类工具
把图片放进剪贴板后，`Ctrl + V` 可能粘不出来；退出 CapsSwitch 就恢复正常。

不是剪贴板本身坏了，而是本程序在键盘输入路径上做了不该做的事，
把系统按键状态或输入时序带乱了。两个都已修掉。

## 根因与改法

**一、注入按键放在了低级键盘钩子回调里**

「单独按 Caps」原先直接在 `WH_KEYBOARD_LL` 回调内 `SendInput` 注入
`Ctrl + Space`。回调跑在系统输入处理路径上，在这里注入按键会重入；
更麻烦的是输入法可能吃掉其中 `Ctrl` 的 KEYUP，而代码既没检查
`SendInput` 返回值、也没有兜底释放修饰键 —— `Ctrl` 一旦卡在按下态，
后面的 `Ctrl + V` / `Ctrl + C` 就会表现异常。

现在改成：钩子只投递一条消息，注入由宿主窗口在正常消息循环里执行；
并且注入结束后**补发一次所有修饰键的 KEYUP**（幂等），
无论 `SendInput` 部分失败还是输入法吞了 KEYUP，都不会留下卡住的 Ctrl。

**二、前台变化回调里做进程查询**

v1.1.0 的「忽略应用」功能会在每次前台窗口变化时调用
`OpenProcess` 查进程名，遇到提权进程还会退化成遍历全系统的
Toolhelp 快照。前台变化回调与低级键盘钩子**共用同一条消息循环**，
这段开销会把钩子回调的派发一起拖慢。截图工具弹工具条、
切换窗口都属于高频前台变化，而图片粘贴走剪贴板延迟渲染
（跨进程 `SendMessage(WM_RENDERFORMAT)`），对输入时序比文本粘贴敏感得多。

现在改成：

- 前台变化回调只记一个 PID 并投递消息，保持 O(1)；
- 进程名解析、忽略判定、托盘刷新统一交给窗口过程，不在输入路径上；
- 按 PID 缓存进程名，同一个进程只解析一次；
- 没配置任何忽略应用时，整条链路零开销；
- 应用选择器里的「最近前台程序」预选也改为点开「添加...」时按需查一次。

## 其他改动

`tools/build_local.sh` 不再硬编码 MSVC 工具集版本号。VS 会自动升级
小版本（本机就从 14.51.36231 升到 14.52.37025），硬编码会在升级后
突然报 `cl: command not found`。现在自动取目录下最新版本，
仍可用 `MSVC_VER` 环境变量显式指定。

## 升级方式

直接退出托盘里的旧实例，用新 exe 覆盖即可。配置文件在
`%APPDATA%\CapsSwitch\config.ini`，升级不会动它。

右键看 exe 属性，版本号应是 **1.1.1**。

## 按键行为（未变）

| 组合 | 行为 |
|---|---|
| 单独按 Caps Lock | 发送你配置的输入法切换快捷键（默认 Ctrl + Space） |
| Shift + Caps Lock | 放行给系统，执行原生大写锁定 |
| Ctrl + Caps Lock | 切换「启用 / 暂停」，两种状态下都有效 |
| Alt / Win + Caps Lock | 只吞掉 Caps，不做任何动作 |
| 暂停状态下 | 除 Ctrl+Caps 外完全不干预 |
| 忽略列表中的程序位于前台 | 以上 Caps 行为全部让路，原样透传 |

另有全局热键 `Ctrl + Alt + C`，与 `Ctrl + Caps` 等效。

## 零运行时依赖

静态 CRT 构建，导入表只有 `ADVAPI32 / COMCTL32 / GDI32 /
KERNEL32 / SHELL32 / USER32` 六个系统 DLL —— 没装 VC 运行库的
机器也能直接跑。CI 会用 `--selftest` 走完初始化链路并扫导入表，
两项都通过才发版。

## 已知限制

- UAC 提权窗口、以及部分以管理员权限运行的全屏程序收不到按键
  （Windows UIPI 机制限制）。需要的话把 manifest 里的
  `requestedExecutionLevel` 改成 `requireAdministrator` 重新编译，
  代价是每次启动弹 UAC。
- 输入法切换快捷键若被其他软件占用，本程序不做规避，
  请在设置里换一种模式（`Win + Space` / `Shift + Space` /
  `Ctrl + Shift + Space`）。
