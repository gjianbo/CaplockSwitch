## 这个版本解决什么问题

用远程控制软件（悠悠远程、ToDesk、向日葵等）时，这些软件自己也要接管 Caps Lock，
而本程序的全局键盘钩子在它之上，会抢先一步把按键吃掉，导致远程端收不到。

新增的**忽略应用**列表让这种冲突有了解法：列表里的程序位于前台时，
本程序对 Caps Lock **完全不表态** —— 单独按、Shift+Caps、Ctrl+Caps、Alt/Win+Caps
全部原样交还给该程序，就像 CapsSwitch 根本没在运行。

## 新增

**忽略应用列表**

在设置窗口的「忽略应用」里点「添加...」选程序，或直接编辑配置文件：

```ini
; %APPDATA%\CapsSwitch\config.ini
[Ignore]
App1=uu.exe
App2=ToDesk.exe
App3=SunloginClient.exe
```

- 最多 16 条，一条一个键
- 只写**进程文件名**，不写完整路径 —— 软件升级、换安装目录都不会让规则失效
- 不区分大小写，没写扩展名会自动补 `.exe`
- 中间某个键留空不影响后面的条目；保存时会把多余的键清理干净

> 注意：命中忽略列表时，`Ctrl + Caps` 也让路，因为那正是「完全不干预」的一部分。
> 此时要暂停 / 启用本程序，请点托盘图标。

**可执行文件带版本信息**

两个 exe 现在写入了 VERSIONINFO，右键属性里能看到版本号（1.1.0），
不再是一片空白。

## 按键行为

| 组合 | 行为 |
|---|---|
| 单独按 Caps Lock | 发送你配置的输入法切换快捷键（默认 Ctrl + Space） |
| Shift + Caps Lock | 放行给系统，执行原生大写锁定 |
| Ctrl + Caps Lock | 切换「启用 / 暂停」，两种状态下都有效 |
| Alt / Win + Caps Lock | 只吞掉 Caps，不做任何动作 |
| 暂停状态下 | 除 Ctrl+Caps 外完全不干预 |

另有全局热键 `Ctrl + Alt + C`，与 `Ctrl + Caps` 等效。

## 已知限制

- UAC 提权窗口、以及部分以管理员权限运行的全屏程序收不到按键。这是 Windows 的
  UIPI 机制限制，不是 bug。需要在提权窗口里生效的话，把 manifest 里的
  `requestedExecutionLevel` 改成 `requireAdministrator` 重新编译，代价是每次启动弹 UAC。
- 如果输入法切换快捷键已被其他软件占用，本程序不做规避，请在设置里换一种模式
  （`Win + Space` / `Shift + Space` / `Ctrl + Shift + Space`）。
