# CapsSwitch —— 简短版（用于 V2EX / 少数派 / 即刻 等快速浏览场景）

**一句话**：把 Caps Lock 变成输入法切换键。单独按 Caps 切中英文，Shift+Caps 保留原生大写，
Ctrl+Caps 随时开关。单文件 122 KB，绿色免安装，零运行时依赖，纯 Win32 手写。

---

## 它解决什么

Mac 用户改不掉的手癖：**按 Caps Lock 切中英文**。
Windows 上 Caps Lock 位置极好、使用率极低，天生就该干这个（macOS 甚至把它做成了官方选项）。

AutoHotkey 要装运行时、要维护脚本；输入法的自定义热键只管自己那一家。
于是写了个专一的：**只做这一件事，做完退回托盘，不再打扰你。**

## 按键表

| 操作 | 反应 |
|---|---|
| 单独按 Caps | 发送输入法切换快捷键（默认 `Ctrl+Space`） |
| Shift + Caps | **完整放行**，原生大写锁定照旧（左右 Shift 都行） |
| Ctrl + Caps | 切换「启用 / 暂停」，**暂停时也能用** |
| Alt / Win + Caps | 只吞掉，不做任何动作 |
| 忽略列表里的程序在前台 | **完全不拦截**，Caps 全部交还给该程序（含 Ctrl+Caps） |

支持 `Ctrl+Space` / `Win+Space` / `Shift+Space` / `Ctrl+Shift+Space` 四种模式，
另有全局热键 `Ctrl+Alt+C` 与 `Ctrl+Caps` 等效。

**忽略应用**：悠悠远程、ToDesk 这类软件自己也要用 Caps Lock，可在设置里把它们加入
忽略列表（或直接写 `config.ini` 的 `[Ignore]` 段，最多 16 条）。它们在前台时本程序
完全不介入。

托盘图标绿 = 启用、灰 = 暂停。

## 设计上想清楚的两点

**1. 暂停之后必须还能唤醒。**
所以键盘钩子**从启动起全程常驻，暂停时也不卸载** —— 识别 `Ctrl+Caps` 本身就依赖它，
它的职责之一正是把程序从暂停态拉回来。一旦暂停就摘钩子，就再没有任何键盘通路能唤醒它了。
于是「启用/暂停」只是一个标志位，语义上「暂停 = 系统原生行为」没有打折。

**2. 切换键选 Ctrl+Caps，不是 Win+Caps。**
Caps 被吞掉后系统认为 Win 是「孤儿键」，会弹开始菜单抢焦点。补救要补发占位按键
（AHK 的 `#MenuMaskKey` 手法，靠 `vkE8`/`vkFF` 这类未文档化键码）—— 那是埋雷。
`Ctrl` 没这个问题，且这个组合本来就是空操作，拿来复用正好。

## 工程上的几个硬约束

- **钩子回调只 `PostMessage`**：回调跑在系统输入处理路径上，托盘刷新、写配置全丢给消息循环做。
- **两条防回环防线**：注入按键带签名识别自己；**任何** `LLKHF_INJECTED` 事件一律放行 ——
  只对物理键盘动作做决策，不碰别的软件注入的按键。
- **「零运行时依赖」用 CI 守住**：扫 PE 导入表，出现 `VCRUNTIME` / `MSVCP` / `ucrtbase` 即失败。
  口号靠不住，断言才靠得住。实测导入表只剩 6 个系统 DLL。
- **`--selftest` 退出码契约**：初始化走完立即退出，全程不弹窗，用退出码（0~6）指明卡在哪一环。
  起因是 CI 里「启动后看进程还在不在」这种断言会被**阻塞的**错误 MessageBox 骗成通过。

## 透明与边界

不需要管理员权限 · 不写系统目录 · 不装服务 · 不联网 · 注册表只碰 `HKCU\...\Run` 的开机启动项 ·
配置只写 `%APPDATA%\CapsSwitch\config.ini`，启动时只读不写 · 删 exe 即卸载干净 · 源码开源，
核心逻辑全在 `hook.cpp` 一个文件里，**就是为了方便单独审查**。

**已知限制**：UAC 提权窗口收不到键盘事件（Windows UIPI 机制，非 bug）·
与其他输入法自带热键可能冲突，请换模式 · 16px 托盘图标下 5 个字母会糊成一条亮带，靠颜色区分状态 ·
Win7 属「未官方支持」（可用 v142/v141 工具集重编）。

## 技术栈

纯 Win32 API · C++17 · 无 MFC / Qt / .NET / 任何第三方库 · 约 1900 行 ·
托盘图标由纯标准库 Python 脚本从两张 PNG 设计稿降采样生成（不含 Pillow）。
